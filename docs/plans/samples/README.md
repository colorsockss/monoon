# 타일맵 샘플 게임 3종 계획

2026-11-25 작성. AI 에이전트 도구(로드맵 17장)는 미루고 이 샘플을 먼저 만든다. 지금까지의 샘플(`PlatformerLab`, `KeyRoomTiles`, `SeedLab` 등)은 기능 하나를 확인하는 실험실이다. 이번 세 샘플은 **처음부터 끝까지 플레이할 수 있는 작은 게임**이다. 엔진 기능을 함께 써 보고, 실제 게임을 만들 때 막히는 곳을 찾는 것이 목적이다.

| 샘플 (가칭) | 타일 레이아웃 | 장르 | 계획 |
| --- | --- | --- | --- |
| **LedgeRun** | Orthogonal | 횡스크롤 플랫포머, 3개 스테이지 | [1-platformer.md](1-platformer.md) |
| **IsoBand** | Isometric | 용병단을 이끄는 캐주얼 액션 RPG, 자동 공격 | [2-iso-rpg.md](2-iso-rpg.md) |
| **HexRealm** | Hex · Pointy | PC 턴제 문명 전략(마우스·키보드), 작은 맵 한 판 | [3-hex-strategy.md](3-hex-strategy.md) |

## 장르 참고와 독창성

- 2번은 '우르르 용병단!'([TapTap 소개](https://www.taptap.io/kr/app/246033))처럼 **여러 영웅으로 된 용병단이 함께 움직이며 자동으로 싸우는 캐주얼 핵 앤 슬래시 RPG**를, 3번은 PC 게임 '문명(Civilization)' 시리즈처럼 **육각 맵에서 도시를 세우고 기술을 연구하며 유닛을 움직이는 PC 턴제 전략**을 장르로 참고한다.
- 참고하는 것은 **장르와 조작 방식**뿐이다. 원작의 이름, 캐릭터, 설정, 그림, 음악, 맵, UI 모양은 쓰지 않는다. 이름·직업·유닛·지형·규칙 수치는 새로 정하고, 그림은 Codex로 샘플 전용 픽셀 아트를 새로 만들고(결정 3), 소리는 합성 효과음을 쓴다. 외부 에셋 팩은 내려받지 않는다.

## 세 샘플의 공통 규칙

- **엔진 규칙**: [AGENTS.md](../../../AGENTS.md)를 따른다. 장르 규칙(전투 공식, 턴 순서, AI)은 엔진 내장이 아니라 **샘플의 프로젝트 스크립트**로 둔다. 여러 장르가 같이 쓸 기능만 엔진에 넣는다(아래 [엔진 보강](#엔진-보강-후보)).
- **편집 방식**: 씬·프리팹·타일셋은 에디터에서 만든다. 맵이 크면 시드 기반 생성 스크립트로 채우고 결과를 씬에 굽는다.
- **배포 확인**: 각 샘플은 macOS arm64에서 Scene Play·Release·Native AOT 기록이 바이트 단위로 같아야 한다. 입력 녹화(`.inputreplay`)를 재생한 trace와 캡처로 비교한다. Linux x64는 게스트에서 Release·AOT를 헤드리스로 재생한다. Windows는 장비가 준비되면 한 번에 확인한다.
- **용량·성능 기록**: 샘플별로 Native AOT 실행 파일과 앱 크기, 첫 프레임 시간, 대표 장면의 프레임 시간과 틱당 할당을 [결과 README](../../../engine/tests/results/) 형식으로 남긴다. 크기 게이트(`./monoon test`)에는 완성 후 넣을지 결정한다(결정 4).
- **하네스**: 샘플마다 `engine/tests/<Sample>.Play/`에 입력 녹화 재생 하네스를 하나 만들고 `engine/tests/harnesses.json`에 등록한다. [하네스 빌드 묶음](../../../engine/tests/results/next1-x64/build-groups.md)의 규칙(시작 씬 하나, 원본 샘플 그대로)에 맞춰 x64 회귀에서 빌드 한 쌍으로 끝나게 한다.
- **매뉴얼**: 샘플마다 매뉴얼 한 장("샘플에서 찾아보기"에서 링크)에 조작법과 어떤 엔진 기능을 어디서 썼는지 적는다. 새 엔진 기능은 해당 매뉴얼과 [구현 기록](../../history/README.md)에 추가한다.

## 엔진 보강 후보

지금 코드로 확인한 부족한 점이다. 샘플을 만들면서 실제로 막히는 것만 구현한다. 모두 여러 장르가 같이 쓸 수 있는 기능이다.

| ID | 필요한 샘플 | 지금 상태 | 보강 내용 |
| --- | --- | --- | --- |
| S1 | 2, 3 | 월드 좌표 → 셀 변환(`TileGrid.Pick`)은 `internal`이고, 스크립트용 공개 API가 없다. 셀 → 월드 중심도 없다. | `IGameObjects.TileCellAt(layer, worldPoint)`, `TileCellCenter(layer, cell)`. 네 레이아웃을 모두 지원하고 레이어의 Transform을 따른다. 마우스로 칸을 고르고, 유닛을 칸 중심에 놓는 데 쓴다. |
| S2 | 3 | `GridNavigation`은 `GridDirections.Four/Eight`만 있다. 육각 이웃(`Tilemap2D.HexEdges`)은 오토타일에만 쓰인다. | `GridDirections.Hex`(6방향, 육각 거리 휴리스틱). `TileNavigation`이 육각 레이어에서 이 방향을 쓴다. 이동 범위(비용 한도 안의 모든 칸)를 돌려주는 `Reachable(start, budget)`도 함께 추가한다. |
| S3 | 2 | 타일 레이어는 한 텍스처로 그려져 칸마다 캐릭터와 앞뒤를 정할 수 없다. | 먼저 **엔진 변경 없이** 벽·나무 같은 키 큰 물체를 Y sort 스프라이트 프리팹으로 둔다. 이 방식이 수백 개에서 느리면 그때 "키 큰 타일만 행 단위로 정렬"을 검토한다. |
| S4 | 2 | 자유 이동 길찾기(`BakeArea`)가 등각 타일의 Solid 칸을 어떻게 굽는지 확인하지 않았다(영역은 축 정렬 상자로 굽는다). | 등각 맵에서 굽기 결과를 확인하고, 틀리면 셀 모양대로 굽도록 고친다. |
| S5 | 3 | 안개(Fog of war)용 기능은 없다. | 엔진 변경 없이 안개 타일 레이어를 따로 두고 `SetTile`로 밝힌다. 맵 1,000칸에서 한 턴의 비용을 재고, 느리면 일괄 갱신 API(`ReplaceTiles` 영역판)를 검토한다. |
| S6 | 1, 2 | 체크포인트·스테이지 진행 저장, 데미지 숫자, 사운드 버스는 이미 있다. | 없음. 샘플에서 쓰는 방법을 매뉴얼에 정리한다. |

## 진행 순서 (추천)

1. **LedgeRun** — 엔진 보강이 거의 필요 없다. 기존 기능을 한 게임에 모았을 때의 문제(씬 전환, 저장, UI 흐름)를 먼저 찾는다.
2. **IsoBand** — S1, S3, S4가 필요하다. 동시에 움직이는 적 100–300마리와 동료 4–6명으로 성능을 확인한다.
3. **HexRealm** — S1, S2, S5가 필요하다. 턴제라 프레임 비용보다 결정성(같은 시드·같은 명령 → 같은 결과)과 저장·리플레이가 중요하다.

샘플마다 "1단계: 최소 플레이 가능 → 2단계: 게임 규칙 완성 → 3단계: 연출·사운드·UI 다듬기 → 4단계: 하네스·배포 검증·문서" 순서로 진행한다.
