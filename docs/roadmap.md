# MoNoon Engine 범용 2D 로드맵

하나의 장르에 맞춘 완성형 시스템보다 여러 장르가 함께 쓸 실행 기능을 먼저 만든다. 아래 항목은 기존 기능을 확장하는 경우까지 포함한 개발 순서다. 장르 규칙(예: 상자 열기, 코인 획득)은 엔진 내장이 아니라 프로젝트 스크립트로 둔다.

## 12. 에디터 화면 개편

현재 에디터는 Hierarchy·Project(176px), Scene, Inspector(218px)가 고정 폭 3열이고 분할선과 탭이 없다. Console·Animator·Tileset·클립·입력 액션·대화·데이터 편집은 각각 별도 창으로 열린다. 이를 패널 단위로 나누어 탭으로 묶고 크기와 위치를 바꿀 수 있게 한 뒤, 전문 엔진 수준의 일관된 디자인을 적용한다.

### 에디터 디자인 기준

- 어두운 바탕 3단계를 쓴다(창 바탕 · 패널 · 입력 필드). 강조색은 선택·포커스·Play 상태에만 쓰고, 경고·오류는 따로 정한 노랑·빨강만 쓴다.
- 기본 글자는 12px로 둔다. 패널 제목과 탭은 12px SemiBold, 보조 정보는 11px 회색으로 한다. 행 높이는 22px, 입력 필드는 24px, 패널 안쪽 여백은 8px로 맞춘다.
- Inspector의 레이블 열은 기존처럼 고정 폭을 쓰고 패널 너비에 따라 입력 열만 늘린다. 긴 이름은 말줄임과 툴팁으로 처리한다.
- 아이콘은 16px 한 벌로 통일하고 글자 없는 버튼에는 툴팁을 단다.
- 매 단계마다 KeyRoom을 연 같은 화면을 캡처해 이전 단계와 비교한다.

## 13. Inspector 개선

2026-11-24 정리. [다음 작업 조사 1](plans/next-work/1-engine-inspector.md)의 Inspector 항목 I-1–I-16을 옮기고 [사용자 결정](plans/next-work/README.md#결정-2026-11-24-사용자-확정) 7–9를 반영했다. 모두 에디터 기능이므로 게임 런타임과 Release·Native AOT 배포본에 에디터 코드를 넣지 않는다. 런타임 데이터를 읽는 13.2·13.3·13.8만 Native AOT 크기 증가를 측정해 남긴다. 각 항목은 macOS arm64 패키지 에디터에서 기존 샘플로 확인하고, 1280·1600·1920px과 긴 이름에서 레이블·입력 열 정렬을 캡처로 비교한다(12.8 방식). 런타임 결과가 바뀌는 항목은 macOS arm64의 Scene Play·Release·Native AOT와 Linux x64 게스트의 Release·Native AOT 헤드리스 재생까지 확인한다. Linux 에디터는 지원하지 않고, Windows 에디터 검증은 장비 준비 후 진행한다.

## 14. 파티클

2026-11-24 정리. [다음 작업 조사 4](plans/next-work/4-particles.md)의 P.0–P.10을 옮기고 [사용자 결정](plans/next-work/README.md#결정-2026-11-24-사용자-확정) 9–11을 반영했다. 설정은 처음부터 `.particles` 에셋에 저장하고, 컴포넌트는 에셋 참조와 인스턴스 값만 갖는다. 그래서 조사의 P.7 에셋 형식은 14.2(에셋 도입)와 14.4(모듈 확장)에 합쳤고, 14.8에는 프리셋과 다시 불러오기만 남겼다. 새 장면은 PlatformerLab·BarrageLab이 아니라 새 ParticleLab 샘플에 만든다. 기존 PlatformerLab 착지 먼지·횃불(4.2)은 호환 회귀로만 쓴다. 시뮬레이션은 Engine.Core, SDL 제출은 Engine.Desktop, 편집 UI는 Engine.Editor에만 둔다. 배포본에는 SkiaSharp를 넣지 않는다(내장 입자 텍스처는 기존처럼 빌드 때 PNG로 굽는다). 상태는 고정 틱에서만 바꾸고, 점 변환·보간은 곱셈·덧셈을 따로 계산하는 `Affine2D`로 한다. `Vector2.Transform`·`Lerp`와 상태 경로의 `MathF.Sin`·`Cos`는 쓰지 않는다([변환 규칙](manual/transform-2d.md)). 입자 트레이스는 같은 OS·아키텍처 안에서 Scene Play·Release·Native AOT가 바이트 단위로 같아야 한다(macOS arm64 필수). Linux x64는 게스트에서 Release·Native AOT 헤드리스 재생으로 확인한다. arm64와 x64의 차이는 기록만 한다. Windows는 장비 준비 후 검증한다. BRUTAL에는 파티클·곡선·그라데이션 기능이 없어 직접 만들고, 그리기는 `Brutal.Sdl`의 RenderGeometry(`SdlSpriteBatch`)를 쓴다. 런타임 증가는 전 단계를 합쳐 IL +40–80 KB(추정)이며, Native AOT 증가는 단계마다 측정해 남긴다.

## 15. 배포 용량·시작 시간

2026-11-24 정리. [배포 빌드 최적화 조사](plans/next-work/2-build-optimisation.md)(B)와 [코드·에셋 trim 조사](plans/next-work/3-trim.md)(T)에서 겹치는 항목을 한 행으로 합쳤고, [사용자 결정](plans/next-work/README.md#결정-2026-11-24-사용자-확정) 2·4–6을 반영했다. 조사 당시 Distribution 빌드는 Release 93–95 MiB(BCL 65 MiB), Native AOT 17.6–19.8 MiB였다(macOS arm64). 목표는 AOT 앱 15 MiB·ZIP 6 MB 이하, Release 30 MiB 이하, 헤드리스 첫 프레임 AOT 30 ms·Release 250 ms 이하다. **하지 않기로 결정**한 항목은 두 가지다. B1 Invariant 전역화는 켜지 않는다(플레이어는 지금처럼 PC 로케일을 따른다).
