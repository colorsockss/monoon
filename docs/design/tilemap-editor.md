# 타일맵 에디터 설계

[KeyRoomTiles](../../samples/KeyRoomTiles/)를 열고 Hierarchy에서 **Floor tiles → Inspector → Edit Tiles**를 누른다. **Tile**에서 썸네일을 고른 뒤 Scene을 드래그하면 바닥을 칠할 수 있다. **Wall**도 같은 방식으로 편집한다. 이 방의 바닥은 통과할 수 있고, Player 바로 아래의 짧은 벽과 문 아래쪽 벽은 이동을 막는다. [실행 및 편집 검증](../../engine/tests/results/tilemap/README.md)

## 타일셋 만들기 → 레이어 칠하기 → Play

1. **Project → + → New Tileset…**: PNG와 원본 셀 크기, 바깥 여백, 셀 간격을 지정한다. 잘린 결과를 미리 본 뒤 타일셋으로 저장한다. Project에서 타일셋을 더블클릭하면 팔레트와 선택한 타일의 충돌 설정을 다시 연다.
2. **Hierarchy 우클릭 → Create Tilemap**으로 빈 오브젝트에 **Tilemap 2D**를 붙인다. 기존 오브젝트에는 **Add Component**로도 붙일 수 있다. **레이어 하나가 Hierarchy 오브젝트 하나**다. 바닥·벽·전경은 별도 레이어로 만들고 일반 스프라이트처럼 Layer/Order로 섞어 그린다. Inspector는 기존 접기 헤더·구분선을 재사용하고 같은 열에 타일셋 선택 필드, 월드 셀 크기, Layer/Order를 정렬한다.
3. **Edit Tiles**를 켜면 해당 레이어에만 격자, 선택 타일, 브러시 미리보기가 보인다. 팔레트에서 타일을 선택하고 Scene에서 브러시·지우개·직사각형·스포이드로 편집한다. 이 모드에서는 좌클릭이 오브젝트 이동에 전달되지 않는다. 팬·줌은 계속 가능하다. Esc 또는 포커스 상실은 진행 중인 획을 취소한다. Play에 들어가면 편집 오버레이와 쓰기를 끄고 Stop하면 원래 레이어로 돌아온다. Mac NSView와 Avalonia 모두 같은 포인터→월드 변환과 획 처리기를 호출한다.

## 데이터 계약: 타일셋은 공유하고 배치는 씬에 둔다

아래는 에디터와 플레이어가 읽는 YAML 형식이다. `.tileset`은 자체 `.meta` GUID를 갖는 에셋이다. `image`는 원본 PNG GUID, `tiles[].id`는 타일셋 안에서만 유일한 양의 정수다. `source`는 애니메이션과 같은 좌상단 기준 픽셀 사각형이다. `tileSize`·`margin`·`spacing`은 재편집용 자르기 설정이다. 팔레트 정렬이나 재슬라이스로 기존 ID를 재번호화하지 않는다. 없어질 ID가 쓰이면 참조 위치와 대체 타일을 보여 주며 해결 전에는 내보내기를 막는다.

```yaml
image: 86212d8d-d170-4413-91a8-62c59b203508
tileSize: {width: 16, height: 16}
margin: 0
spacing: 0
tiles:
- id: 1
  source: {x: 0, y: 0, width: 16, height: 16}
  solid: true
```

씬의 `Tilemap2D` 컴포넌트는 타일셋 GUID 하나와 **월드 단위** 셀 크기를 갖는다. 셀당 오브젝트·컴포넌트·`.meta`는 만들지 않는다. 배치는 32×32셀 단위인 청크로 나누고 비어 있지 않은 셀만 기록한다. `0`은 빈 셀로 메모리에서만 사용한다. 저장 순서는 청크 `(y,x)`, 청크 안에서는 `index = localY × 32 + localX` 오름차순이다. 빈 청크는 저장하지 않는다.

```yaml
type: tilemap2D
tileset: c4f3f20f-b773-4722-8cd6-c9bdb4c88391
cellSize: {width: 32, height: 32}
sortingLayer: 0
order: -1
chunks:
- x: -1
  y: 0
  cells: [{index: 31, tile: 1}]
```

위 예시는 **월드 원점이 (0,0)인 레이어에서 셀 (-1,0)**에 16×16 원본 타일을 월드 32×32로 그린다. 직교 격자는 포인터의 월드 위치에서 부모 변환을 포함한 레이어 원점을 빼고 셀 크기로 나눈 뒤 내림한다. 청크도 내림 나눗셈을 사용하므로 월드 x=-1은 청크 -1, 로컬 x=31이다. 저장·그리기·충돌·선택 모두 이 함수를 공유한다. 프리팹이나 계층 복제 시 타일셋 참조는 공유하되 배치 데이터는 불변 청크 또는 깊은 복사로 분리한다.

재슬라이스로 사용 중인 ID가 사라질 때 **Save Tileset**을 누르면 사용 위치를 표시한다. 시트에서 대체 셀을 고르고 **Use selected tile**을 누른다. 대체 셀의 원본 영역과 Solid 설정을 기존 ID에도 연결하므로 다른 씬과 프리팹에서도 같은 결과를 본다.

## 구현 순서와 완료 기준

| 단계 | 구현할 곳과 결정 | 통과 조건 |
| --- | --- | --- |
| 1. 에셋·저장·빌드 | [ProjectAssets](../../engine/src/Engine.Core/ProjectAssets.cs)에 타일셋을 등록하고 [SceneComponent](../../engine/src/Engine.Core/SceneComponent.cs)에 VYaml union `tilemap2D`를 추가한다. 타일맵 도입 시 다음 씬 스키마는 기존 v6과 UI가 도입된 v7을 읽으며, 단순 열기로 기존 원본을 다시 쓰지 않는다. 프리팹 및 씬 편집 기록의 복원에도 새 컴포넌트를 등록한다. [GameBuild](../../engine/src/Engine.Core/GameBuild.cs)는 포함 씬/프리팹 → 타일셋 → PNG를 추적한다. | v6 KeyRoom 재열기, 타일 레이어의 저장·재열기·복제·프리팹 인스턴스 편집을 확인한다. 원본/다른 인스턴스 배치가 바뀌면 실패다. 없는 타일 ID, 잘못된 index, 중복 셀, 누락 PNG 또는 구형 템플릿은 위치를 알리는 오류로 막는다. |
| 2. Scene 편집·Undo | 누를 때 획을 열고 포인터가 건너뛴 중간 셀도 채운다. 놓을 때 변경된 셀의 처음·마지막 값만 모아 기록한다. 기존 [SceneHistory](../../engine/src/Engine.Editor/SceneHistory.cs)의 씬 전체 스냅샷과 셀 차이 기록을 **한 시간순 Undo/Redo 목록**에 넣는다. 저장 기준점과 새 편집 후 Redo 폐기도 공유한다. | 여러 청크에 걸친 한 획을 ⌘/Ctrl+Z 한 번에 되돌린다. 오브젝트 이동 → 칠하기 → Undo 두 번/Redo 두 번에서 순서가 맞는다. 저장 후 다시 열어 음수 좌표와 격자 경계가 같고 취소한 획은 남지 않는다. |
| 3. 그리기·정렬 | [SceneDocument.DrawOrder](../../engine/src/Engine.Core/SceneDocument.cs)의 정렬 기준을 월드 그리기 항목에 공통 적용한다. Layer → Order → 같은 값이면 씬 내 순서로 그린다. 같은 오브젝트에 두 렌더러가 있으면 타일맵이 먼저다. HUD는 월드 뒤에 별도로 그린다. 활성 카메라/편집 뷰와 겹치는 청크만 조회하고 같은 PNG를 공유한다. | 배경 타일 → Player → 전경 타일 순서가 편집·Play·게임에서 같다. 카메라 교체·줌·창 리사이즈에도 가장자리 셀이 빠지지 않는다. 멀리 떨어진 청크를 수백 개 추가해도 같은 뷰에서 그린 청크·타일 수는 늘지 않는다. |
| 4. 정적 벽 충돌 | `solid`인 타일의 월드 사각형만 후보로 쓴다. 이동체의 시작~도착 범위에 걸친 셀을 조회해 [기존 연속 박스 충돌](../../engine/src/Engine.Core/BoxCollision.cs)에 일반 벽과 함께 전달한다. 장식 타일은 통과한다. 셀마다 Box Collider 오브젝트를 만들지 않는다. | 고속 이동·대각선 이동·청크 경계에서 벽을 통과하지 않고 벽을 따라 움직인다. 일반 문과 열쇠 트리거는 기존대로 동작한다. 저장·재열기 후에도 같은 위치에서 막힌다. |

**최종 플레이 검증**: 원본을 보존한 KeyRoom 복사본에서 벽 일부를 solid 타일로 교체한다. Mac 에디터 Play → Mac Release/Native AOT → Windows/Linux x64 Release 순서로 시작 방의 벽, 열쇠 획득, 둘째 방 전환을 확인한다. 기존 자동 검사는 둘째 방의 특정 벽·HUD 픽셀을 보므로 그 기준 화면은 보존하거나 타일맵 샘플에 별도 기대 화면을 둔다. 각 OS의 에디터 편집 검증은 플레이어 결과와 별도로 남긴다.

현재 에디터는 정적 직교·아이소메트릭·육각형(꼭짓점 위·평평한 면 위) 격자를 지원한다. 레이어마다 타일셋 하나와 Layout을 지정한다. 비직교 격자의 선택, 가이드, 텍스처와 Solid 충돌은 같은 셀 외곽을 사용한다. 자동 타일, 애니메이션 타일, 이동 발판과 단방향 충돌은 후속 범위다. [격자별 사용법과 예제](../manual/tilemaps.md)
