# KeyRoom 가방의 가장자리 고정과 해상도 미리보기

배포 에디터에서 KeyRoom을 열고 **Scene → UI Layout Preview…**에서 언어를 `ko`, 글자 크기를 200%로 지정했다. 아래 좌표는 에디터 창의 물리 픽셀이 아닌 게임의 논리 픽셀이다. 각 해상도에서 가방은 왼쪽·오른쪽 64, 위·아래 36의 여백을 유지했다.

| 미리보기 | 가방 너비 × 높이 | 닫기 버튼 왼쪽 X | 닫기 버튼 아래쪽 Y |
| --- | ---: | ---: | ---: |
| 640 × 360 | 512 × 288 | 430 | 306 |
| 800 × 450 | 672 × 378 | 590 | 396 |
| 1024 × 768 | 896 × 696 | 814 | 714 |
| 480 × 720 | 352 × 648 | 270 | 666 |

**입력**은 운영체제의 I 키로 가방을 연 뒤, 닫기 버튼 네 변의 중앙에서 각각 3픽셀 바깥과 3픽셀 안쪽을 눌렀다. 바깥 클릭 후에는 가방이 열려 있고 안쪽 클릭 후에는 닫혀야 한다. 나침반 관리 버튼은 중첩 확인창을 열어야 한다. 글자 배율 200%에서 언어 버튼·아이템·의뢰·하단 버튼이 겹치는지도 검사했다.

**편집**에서는 800×450를 유지한 채 Inspector에서 가방의 오른쪽 여백을 64에서 124로 수정했다. 가방 폭과 자식 버튼 오른쪽 끝이 60씩 줄고 Undo 한 번으로 복원돼야 한다. 미리보기 창 폭 310과 270에서 입력 필드의 왼쪽 정렬도 확인했다. **Use Project** 적용 뒤에는 최초 `GameSettings`와 `KeyRoom.scene` 바이트를 대조했다. 카메라 없는 RoomGuide 씬에서는 640×360 캔버스가 Scene 중앙에 보이는지 확인했다.

## 배포 에디터의 Scene Play

각 환경에서 닫기 버튼 안쪽 클릭 16회와 바깥쪽 클릭 16회를 보냈다. 화면 캡처에서는 가방의 채움색으로 그려진 영역을 찾고, 그 안에서 버튼 양 끝의 예상 위치와 실제 채움색의 경계 사이 거리를 측정했다. 오차는 캡처의 물리 픽셀 단위다.

| 환경 | 네 해상도의 입력·Undo·설정 복원 | 버튼 경계 최대 오차 | 세로 화면 |
| --- | --- | ---: | --- |
| macOS arm64 | [통과](osx-arm64/result.json) | [0.52 px](osx-arm64/pixels.json) | [480×720](osx-arm64/bag-480.png) |
| Windows 11 Enterprise LTSC x64 VM | [통과](win-x64/result.json) | [1.42 px](win-x64/pixels.json) | [480×720](win-x64/bag-480.png) |
| Debian 12 x64 VM | [통과](linux-x64/result.json) | [1.55 px](linux-x64/pixels.json) | [480×720](linux-x64/bag-480.png) |

Windows QEMU에서는 검사 훅이 에디터의 Scene 갱신 간격을 100ms로 설정했다. 초기 캡처 두 장에서 직전 편집 화면이 발견되어, 가방의 네 변이 예상 화면 좌표에 그려질 때까지 기다리도록 드라이버를 수정했다. 표에는 보강한 검사로 다시 실행한 결과를 기록했다.

## 독립 게임

이 Mac에서 다시 빌드한 KeyRoom Release와 Native AOT에 같은 18프레임·16이벤트를 재생했다. 기본 해상도 800×450에서 닫기 버튼 밖을 누르고 F5를 보냈을 때 2번 저장 슬롯은 생기지 않았다. 안쪽을 눌러 가방을 닫은 뒤에는 1번 슬롯이 저장됐다. 두 파일 모두 108바이트이며 SHA-256은 `75bbe69fa563e7ee4d67e490e16ee3d03be2c84a8b1be2418f1ee856deea5e7b`이다. 두 앱의 파일 목록과 실행 파일의 링크 대상도 확인했다.
