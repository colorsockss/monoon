# SeedLab 배달원 길찾기 검증

시작 씬에서 **G**로 배달원 씬에 들어간 뒤 같은 1,420프레임의 입력 기록으로 여섯 번 이동했다. 관찰 스크립트는 샘플 복사본에서 배달원의 실제 Transform이 바뀔 때마다 좌표를 기록했다. 모든 이동을 이웃 칸 단위로 검사하고, 별도로 계산한 다익스트라 최소 비용과 대조했다. [입력과 검사 코드](../../SeedLab.GridNavigation/verify.py) · [전체 방문 순서](routes.tsv)

| 조건 | 걸음 | 총비용 | 방문 결과 |
| --- | ---: | ---: | --- |
| 4방향 · 닫힌 문 | 16 | 160 | 북쪽 마른 길로 우회 |
| 4방향 · 열린 문 | 10 | 100 | 문을 지나는 직선 |
| 8방향 · 닫힌 문 | 14 | 148 | 북쪽 길에서 대각선 2회 사용 |
| 8방향 · 열린 문 | 10 | 100 | 문을 지나는 직선 |
| 8방향 · 닫힌 문 · 진흙 비용 1배 | 10 | 108 | 진흙 3칸을 밟아 남쪽으로 통과 |
| 4방향 · 걷는 중에 문 열기 | 12 | 120 | 두 걸음 뒤 (2, 3)에서 남은 경로를 갱신하고 (6, 4)의 문을 통과 |

기본 진흙 비용은 12배다. 모든 경우에 배달원이 목적지 (11, 4)에 도착했다. 대각선 이동마다 양옆의 칸이 열려 있는지도 검사했다. 걷는 중에 문을 연 경우 표에는 출발점부터의 전체 비용을 표시했다.

## 실행 환경

| 환경 | Scene Play | Release | Native AOT |
| --- | --- | --- | --- |
| macOS arm64 | 6/6 | 6/6 | 6/6 |
| Windows 11 Enterprise LTSC x64 · QEMU | 6/6 | 6/6 | 6/6 |
| Debian 12 x64 · QEMU | 6/6 | 6/6 | 6/6 |

각 OS에서 패키지 에디터의 Play 버튼으로 시작했다. Debian 에디터는 Xvfb에서 실행했다. 독립 게임은 각 OS에서 배포 프로필로 빌드하고 플레이어의 헤드리스 입력 재생으로 검사했다. 아홉 실행 모두 입력 전환과 좌표를 기록한 88개 행이 같았다. 여섯 경로를 담은 결과 파일의 SHA-256도 일치했다. [실행별 결과 해시](runs.tsv)
