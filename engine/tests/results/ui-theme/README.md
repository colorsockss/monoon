# KeyRoom 버튼 테마와 9-slice Mac 검증

macOS 27.0.1 arm64에서 MoNoon.app의 Scene Play와 Distribution 프로필로 빌드한 Release·Native AOT 앱을 각각 실행했다. 실제 창에 키와 마우스 입력을 보내고 캡처에서 버튼 색, 테두리 무늬, 클릭 후 패널의 표시 여부를 읽었다.

| 실행 | 한글 200% | 창을 줄인 뒤 | 닫기 버튼 경계 |
| --- | --- | --- | --- |
| Scene Play | [방 안내](play-ko-200.png) | [970 × 715 에디터](play-resized.png) | 네 변 바로 밖에서 유지, 오른쪽 아래 바로 안에서 닫힘 |
| Release | [방 안내](release-ko-200.png) | [722 × 590 게임 창](release-resized.png) | 같은 결과 |
| Native AOT | [방 안내](aot-ko-200.png) | [722 × 590 게임 창](aot-resized.png) | 같은 결과 |

**입력과 표시.** 기본 영문 상태에서 M으로 안내를 열고 L로 한글로 바꿨다. 닫기 버튼에 포인터를 올리고 마우스를 누른 채 밖으로 끌어 놓았다. 눌림이 취소되고 포커스가 남았다. 글자 크게를 두 번 눌렀을 때 본문과 버튼이 한글 100%, 150%, 200%로 재배치됐다. 200%에서 크게 버튼을 다시 눌러도 배율과 패널 높이는 유지됐다. 세 경로에서 관찰한 기본·호버·포커스·눌림·비활성 배경색이 서로 같았다. [캡처 측정값](measurements.json)

**패널 모서리.** 24 × 24 PNG의 네 방향에 8픽셀 테두리를 지정했다. 게임 해상도에서 방 안내 폭은 426으로 유지되고 높이는 약 159에서 318로 늘어났다. 같은 창의 한글 100%와 200% 캡처에서 각 모서리의 16개 색 표본이 전부 일치했다. 창을 줄인 뒤에도 네 변의 색 띠 순서가 유지됐고, 각 모서리 장식의 중심은 원본 위치에서 물리 화면 1픽셀 이내에 있었다. Release와 Native AOT의 한글 200% 패널을 잘라 픽셀을 비교한 결과도 일치했다.

**클릭과 조작 안내.** 크기를 바꾼 창에서 닫기 버튼의 왼쪽·오른쪽·위·아래 바깥을 차례로 클릭했다. 네 번 모두 방 안내가 유지됐다. 같은 창의 버튼 오른쪽 아래 경계 안쪽을 클릭하자 닫혔다. 이후 H로 조작 안내를 열고 닫았고, 긴 한글 조작 설명도 같은 이미지의 테두리 안에서 줄바꿈됐다. [조작 안내 화면](play-controls.png)

**에디터 편집.** 사본에서 긴 이름의 테마 파일을 선택하고 UI Accessibility 창을 너비 340으로 줄였다. Button theme, Text table, Default font의 입력 열이 같은 X 좌표와 너비를 유지했다. 너비 900의 Inspector에서는 L / R과 T / B 두 행에서 각각 왼쪽·오른쪽 숫자 입력란의 시작과 끝 위치가 일치했다. [테마 선택 창](compact-theme.png) · [이미지 Inspector](compact-drawer.png)

엔진 회귀 검사에서는 비대칭 테두리, 목적지가 테두리 합보다 작은 경우, 유효하지 않은 원본 경계, 입력 취소, 키보드 활성화와 비활성 버튼도 검사했다. [회귀 코드](../../Engine.Checks/UiThemeChecks.cs) · [사용법](../../../../docs/manual/game-ui.md#버튼-테마와-9-slice)
