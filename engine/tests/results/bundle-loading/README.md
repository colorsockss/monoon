# InventoryLab 대용량 번들 측정

2026-11-16, macOS 27.0.1 arm64, Apple M4 Max, .NET SDK 10.0.101. 배포 프로필로 빌드한 두 앱을 이 Mac의 SDL 창에서 직접 실행했다. InventoryLab 시작 씬에서 약 5분 50초의 스테레오 시장 배경음을 반복 재생한다. PCM WAV는 67,108,908바이트, `Market.bundle`은 51,326,509바이트다. 두 빌드의 시장 번들 SHA-256은 `4a081d6294c5b841148d6f803315975793cf39bd35eab55bf6111b4b572d8456`으로 같다. 작은 대화·의뢰 번들도 함께 읽었다.

## 결과

시간은 각 조건 5회의 중앙값이다. 최장 프레임 열에는 각 실행의 최댓값을 모은 중앙값과 다섯 실행 전체의 최댓값을 함께 표시했다. 디스크는 5회 중 가장 큰 파일 길이의 합이며, MiB는 1,048,576바이트다.

| 배포본 | 앱 캐시 | 번들 준비 (ms) | 시장 번들 읽기 (ms) | 첫 조작 (ms) | 최장 프레임 중앙값 / 최악 (ms) | 임시 / 지속 캐시 (MiB) |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| Release | 사용 안 함 | 365.7 | 233.8 | 929.9 | 74.4 / 81.0 | 64.05 / 0.00 |
| Release | 최초 생성 | 368.0 | 234.1 | 920.6 | 74.4 / 77.1 | 0.00 / 64.05 |
| Release | 재사용 | 67.2 | 22.7 | 597.4 | 72.3 / 72.6 | 0.00 / 64.05 |
| Native AOT | 사용 안 함 | 350.8 | 233.2 | 714.8 | 31.7 / 38.3 | 64.02 / 0.00 |
| Native AOT | 최초 생성 | 350.9 | 233.9 | 724.5 | 31.1 / 32.9 | 0.00 / 64.02 |
| Native AOT | 재사용 | 57.4 | 23.1 | 427.2 | 32.0 / 33.7 | 0.00 / 64.02 |

`off`는 같은 바이너리에서 캐시를 끈 기존 압축 해제 경로다. `miss`는 비어 있는 게임 프로필에서 시작했고 `hit`는 직전 실행이 종료된 뒤 같은 캐시를 사용했다. 최초 생성 때는 시장 WAV 67,108,908바이트를 풀었고 재사용 때는 0바이트를 풀었다. 매 실행마다 배포 번들의 SHA-256을 확인했다. 재사용 시 풀린 파일까지 검사하는 비용은 전체 번들 준비 시간에 포함된다.

캐시 재사용 시 번들 준비 시간은 Release에서 81.6%, Native AOT에서 83.6% 줄었다. 프로세스 시작부터 첫 조작까지는 각각 35.8%, 40.2% 줄었다. 최초 생성의 준비 시간은 두 빌드 모두 기존 경로와 3 ms 이내였다. 캐시 재사용에 따른 최장 프레임 중앙값의 차이는 두 빌드 모두 3 ms 이내였다.

30회 모두 첫 액션은 `AddHerb`였다. 이어서 S로 저장한 슬롯에 약초 한 개가 있었고, 30개 슬롯의 SHA-256은 모두 `9ae57ef4c0825c6d1b9b3eb5619fac21ac6a59f1fc6370e298c4da9c71aaea30`였다. 정상 종료 후 번들용 임시 폴더는 매번 사라졌고, 캐시를 켠 실행에서는 검증된 파일 한 벌이 프로필에 남았다. 기존 약초 의뢰 입력도 별도로 두 빌드의 최초 생성·재사용 경로에서 각각 재생했다. 네 번 모두 475프레임·31개 이벤트를 처리했고 최종 171바이트가 맥 기준 저장과 일치했다. ## 측정 범위

- 측정기가 프로세스를 시작하기 직전부터 첫 화면을 기다린 뒤 전면 SDL 창에 macOS 숫자 1 키를 보내고, 엔진이 약초 획득을 처리한 시뮬레이션 틱의 완료를 관찰할 때까지를 첫 조작 시간으로 쟀다. 창 활성화·입력 전달·1 ms 폴링 지연을 포함한다. CSV에는 플레이어 진입 기준 첫 화면과 첫 조작 시간도 따로 있다.
- VSync를 켜고 루프 시작부터 첫 화면 표시까지와 이후 `RenderPresent` 완료 사이 간격을 첫 120프레임 동안 측정했다. 번들 준비는 창을 열기 전에 끝난다. 최장 프레임에는 첫 UI 렌더링과 표시 대기도 들어간다.
- 10 ms마다 게임의 전용 임시 경로와 프로필의 번들 캐시를 조사했고 화면 표시 후에도 한 번 더 읽었다. 파일 길이와 파일별 할당 블록 수(`st_blocks × 512`)를 각각 기록했다. 저장 슬롯·배포 앱·OS의 가상메모리는 측정 범위 밖이다.
- 빌드 종류와 캐시 끄기 조건의 실행 순서를 매 반복마다 바꿨다. OS 파일 캐시는 유지했다. 이 부하는 큰 오디오 한 개와 작은 YAML 번들 두 개를 읽는 경우를 대표한다.

## 재현

저장소 루트에서 실행한다. 측정기는 Xcode 명령줄 도구로 테스트용 키 입력기를 임시 폴더에 컴파일한다. 게임 창이 순서대로 열리며 결과 CSV는 새 파일로 작성한다.

```sh
engine/scripts/build-players.sh osx-arm64
./monoon build samples/InventoryLab release --profile distribution --output game-builds/InventoryLab-Bundles
./monoon build samples/InventoryLab native-aot --profile distribution --output game-builds/InventoryLab-Bundles
python3 engine/tests/InventoryLab.Bundles/measure_mac.py game-builds/InventoryLab-Bundles /tmp/inventory-startup-runs.csv
```

측정한 Release 빌드 ID는 `3e97ae6c7cc24d3e8e25b80336adf054`, Native AOT는 `ffc2c087e34f452789ea1eff2df0c862`다. 캐시 손상·동시 실행·오버라이드 격리·중단 복구·배포 원본 변조에 관한 엔진 회귀 검사도 통과했다.
