# CardLab 셔플과 저장 복원 검증

2026-11-14, macOS 27.0.1 (26A434), Apple Silicon arm64. 에디터에서 CardLab을 열어 Scene Play를 실행하고, macOS Release와 Native AOT로 내보낸 독립 게임도 각각 실행했다. 세 경로에 분리된 임시 프로필을 사용했다.

| 확인 항목 | 세 실행에서 관찰한 결과 |
| --- | --- |
| 첫 셔플 | 시드 42는 샛강 → 돌다리 → 별마루 → 달고개 → 이슬길 → 솔숲이었다. 시드 43은 솔숲 → 달고개 → 별마루 → 이슬길 → 샛강 → 돌다리였다. R로 42를 다시 시작했을 때 첫 저장과 일치했다. [시드 42 원본](start.save) |
| 뽑기와 사용 | 클릭과 D로 세 장을 뽑고 손패 두 번째의 돌다리를 클릭했다. 손에 샛강·별마루, 버린 더미에 돌다리, 덱에 달고개·이슬길·솔숲이 남았다. 이동 거리는 2칸이었다. [중간 저장](mid.save) |
| 앱 재실행 | 중간 저장 사본을 임시 프로필의 슬롯 1에 다시 놓고 새 프로세스에서 L을 눌렀다. 손패·남은 덱·버린 카드·이동 거리가 모두 복원됐다. S로 재저장한 파일이 원래 중간 저장과 바이트 단위로 일치했다. |
| 버린 카드 재셔플 | 이어서 D로 남은 세 장을 뽑고 손패 첫 번째를 다섯 번 사용했다. 빈 덱에서 D를 누르자 셔플 차수가 2가 되고, 버린 여섯 장 중 이슬길 한 장만 손으로 왔다. 나머지 다섯 장까지 뽑았을 때 손패 순서는 이슬길 → 솔숲 → 샛강 → 돌다리 → 달고개 → 별마루였다. [재셔플 직후](resumed-recycle.save) · [여섯 장을 뽑은 뒤](resumed-all.save) |

복원 결과는 같은 중간 상태에서 종료 없이 진행한 경로와 대조했다. 두 경로는 첫 덱을 다 뽑은 직후, 재셔플에서 한 장을 뽑은 직후, 여섯 장을 모두 뽑은 뒤 저장 파일이 각각 일치했다. 시드 변경·재시작을 포함해 실행 경로당 11개, 총 33개 체크포인트를 비교했다. [파일별 SHA-256](checkpoints.csv) · [UI 인식 텍스트와 실제 저장값](observations.txt)
