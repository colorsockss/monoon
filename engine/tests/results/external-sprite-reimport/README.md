# 외부 PNG 재임포트 검증

2026-11-17에 패키징한 MoNoon 에디터에서 KeyRoom 복사본을 열었다. Scene은 닫힌 문의 원본인 `Door.png`를 사용하고, `Door.clip`은 `DoorSheet.png`의 셀을 사용한다. 순서와 재생 시간의 변화를 구별하기 위해 검증용 복사본의 네 프레임 시간을 각각 **0.11, 0.23, 0.37, 0.49초**로 설정했다. 배포하는 KeyRoom 샘플의 기본 시간은 각각 0.09초다.

| 단계 | 외부 편집과 검증 |
| --- | --- |
| 열어 둔 상태 | 첫 프레임의 시간 입력란에 `0.173`을 입력한 상태에서 다른 프로세스가 원본 PNG를 초록색으로 덮어썼다. 헤더와 나머지 데이터를 나눠 쓰고 수정 시각을 원래 값으로 복구했다. 포커스를 전환하기 전에 Project, Scene, 클립 미리보기, 타임라인의 새 픽셀을 모두 확인했다. 입력란의 초안도 유지되어 원래 값으로 되돌렸다. |
| 포커스 복귀 | 별도 창으로 포커스를 옮긴 뒤 임시 PNG를 보라색 문 PNG로 원자적으로 교체했다. 메인 창과 클립 창을 활성화해 네 곳의 색과 네 프레임의 셀·시간을 확인했다. |
| 에디터 재실행 | 에디터 프로세스를 종료하고 디스크의 원본 PNG를 파란색으로 바꿨다. 에디터와 클립을 다시 열어 같은 네 곳의 파란색 픽셀과 프레임 정보를 확인했다. |

각 단계에서 시트 GUID `cc19244c-3e31-5d09-8c09-f934790a4e27`와 셀 `(0,0,24,94)`, `(24,0,24,64)`, `(24,64,24,32)`, `(0,94,1,1)`을 대조했다. 클립과 씬 파일은 테스트 시작 시점의 바이트와 일치했다. 같은 시트의 다른 문 프레임 픽셀도 유지됐다. 잘린 PNG와 셀 크기를 넘는 원본을 거절한 뒤 올바른 파일로 복구하는 경우는 엔진 회귀에 포함했다. [회귀 코드](../../Engine.Checks/SpriteReimportChecks.cs)

아래 캡처는 에디터의 네 영역을 같은 순서로 잘라 붙인 것이다. Mac에서는 Project와 타임라인을 원본 색과 대조하고, SDL Metal로 그리는 Scene과 클립은 클립 중앙에 실제로 표시된 색을 기준으로 대조했다. 결과 JSON에는 표시된 픽셀 수, 네 프레임의 좌표·시간과 검증용 클립의 SHA-256이 있다. `secondsWaiting`은 시트 갱신 확인 후 화면 캡처와 픽셀 비교에 걸린 시간이다. [검증한 에디터 어셈블리 해시](editors.sha256)
