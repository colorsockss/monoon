# KeyRoom 월드 포인터 검증

2026-11-17에 세 운영체제의 배포 에디터에서 같은 KeyRoom 샘플 ZIP을 열고 실제 OS 마우스·키보드 입력으로 **Play → F8**을 실행했다. `PointerWorkshop`의 주 카메라는 1배, 오른쪽 위 카메라는 1.4배다. 검증용 프로브는 에디터 컨트롤의 화면 좌표, 각 상자의 월드 좌표, 카메라 중심과 게임에 표시된 문구를 읽었다. [직접 조작하는 방법](../../../../docs/manual/input-actions.md#월드-오브젝트-클릭과-드래그)

| 배포 에디터 · Scene Play | 카메라 X 이동 | 앞 상자 X 이동¹ | 뒤 상자 월드 위치¹ | UI 클릭 | 증거 |
| --- | ---: | ---: | --- | ---: | --- |
| macOS 27.0.1 arm64 | +100 | +100 | (240, 168) | 1 | [수치](osx-arm64.json) · [화면](osx-arm64.png) |
| Windows 11 Enterprise LTSC x64 · QEMU | +100 | +100 | (240, 168) | 1 | [수치](win-x64.json) · [화면](win-x64.png) |
| Debian 12.15 x64 · QEMU, X11/Xvfb | +100 | +100 | (240, 168) | 1 | [수치](linux-x64.json) · [화면](linux-x64.png) |

¹ 마우스를 누른 채 커서를 고정하고 D를 눌러 주 카메라의 중심을 (400, 225)에서 (500, 225)로 옮긴 구간이다.

- 앞뒤 상자가 겹친 곳의 **UI clicks**에서 누르고 버튼 안에서 조금 움직인 뒤 놓았다. 버튼 횟수가 0에서 1로 바뀌었고 두 상자의 좌표와 월드 입력 상태 문구가 그대로였다.
- 버튼 아래의 겹친 부분을 클릭하자 `Front crate / Click`이 표시됐다. 같은 곳을 누른 채 오른쪽 아래로 끌자 앞 상자만 움직였다. 커서를 고정하고 카메라를 옮겼을 때 앞 상자의 월드 X가 430.159에서 530.159로 바뀌어 화면에서 잡은 지점의 오차는 0이었다. 놓으면 `Front crate / Release`가 표시됐다.
- 확대 화면에서 파란 상자를 잡아 주 화면까지 끌고 놓았다. `Back crate / Release`가 표시됐고 앞 상자는 제자리에 남았다. 뒤 상자의 최종 위치와 확대율로 환산한 예상 위치의 차이는 세 환경 모두 0.242 월드 단위였다. 허용 오차는 OS 포인터를 정수 화면 좌표에 놓는 것을 고려해 2.5로 두었다.

## macOS 독립 게임

같은 Mac에서 배포 프로필의 Release와 Native AOT 앱을 각각 실행했다. F8로 작업실을 열고 OS 입력으로 같은 조작을 한 뒤 SDL 창에 그려진 두 상자의 왼쪽 위를 게임의 800 × 450 논리 해상도로 측정했다. 두 빌드에서 아래 결과가 모두 일치했다. [Release 수치](mac-release.json) · [Native AOT 수치](mac-native-aot.json) · [최종 화면](mac-native-aot.png)

| 주 화면의 위치 | 주황 상자 | 파란 상자 |
| --- | --- | --- |
| 입장 및 UI 버튼 클릭 직후 | (300, 198) | (240, 168) |
| 주황 상자를 드래그한 뒤 | (431, 261) | (240, 168) |
| 포인터를 고정하고 카메라를 오른쪽으로 100 이동 | (431, 261) | (140, 168) |
| 확대 화면에서 파란 상자를 집어 밖에서 놓은 뒤 | (431, 261) | (75, 185) |

`./monoon test`에 같은 샘플의 입력 회귀 검사를 포함했다. 회전된 오브젝트를 잡은 로컬 좌표, 빈 카메라 화면에서 뒤의 오브젝트를 클릭하는 경우, 포인터 초기화와 오브젝트 제거 중 취소도 검사한다. [회귀 검사](../../Engine.Checks/WorldPointerChecks.cs)
