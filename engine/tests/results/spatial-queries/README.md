# CollisionLab 대형 씬 물리 질의 검증

2026-11-17 같은 엔진 소스에서 내보낸 세 플랫폼의 Release 배포 플레이어를 실행했다. 두 씬 모두 공간 인덱스를 켰을 때와 껐을 때 288개 질의의 적중 대상과 순서가 모두 일치했다. 세 OS의 대상 ID 해시와 후보 수도 일치했다.

## 후보 수와 p95 질의 시간

## 측정 방법

- 각각 정확히 1,000개와 10,000개의 박스·원·볼록 삼각형을 씬에 배치했다. 각 씬에서 좌표, 레이어, 트리거 여부, 도형과 입력을 고정한 채 두 모드를 번갈아 실행했다. 같은 위치의 두 박스는 겹침 결과의 순서와 같은 거리에 있는 첫 적중의 우선순위를 검사한다.
- 고정 시드로 만든 경로 96개에 겹침·레이캐스트·스윕을 한 번씩 실행한다. 각 방식의 288개 질의를 한 차례 예열한 뒤 측정 순서를 바꿔 가며 6회 반복한다. 종류별로 방식당 576개 표본이다. 매번 겹침 결과 전체의 순서와 레이어·트리거 상태, 레이·스윕의 적중 대상·거리·비율·점·법선을 원본 결과와 비교한다. OS 간 비교용 SHA-256은 질의 순서대로 적중 ID를 기록한 해시다.
- 후보는 공간 검색에서 꺼내 필터와 도형 검사의 대상으로 삼은 고유 오브젝트 수다. 전체 순회는 트리거 제외 질의에 기존 일반 충돌체 목록을 사용한다. 격자는 겹치는 셀의 충돌체를 한 번만 센다. 타일 셀은 별도로 검색하며 이 샘플에는 없다.
- 세 OS 모두 렌더링 창을 열지 않고 같은 게임의 고정 틱과 스크립트를 실행했다. Release 런타임에는 `DOTNET_TieredCompilation=0`을 적용했다. 단조 시계로 각 물리 API 호출을 재고 정렬한 시간 표본의 `ceil(0.95 × n)`번째 값을 사용했다. 씬 로딩·격자 생성/갱신·결과 비교·렌더링은 타이머 밖에 있다.
- Mac에서는 게임 창에서 숫자 키로 두 씬을 전환하고 HUD도 확인했다. 이 별도 실행의 화면에는 그때 측정한 시간이 표시된다. [1만 개 씬의 게임 창](field10000.png)

## 재현

저장소 루트에서 현재 OS용 Release 템플릿과 CollisionLab을 빌드한다. 아래는 macOS arm64의 예다.

```sh
./engine/scripts/build-players.sh osx-arm64
./monoon build samples/CollisionLab release --target osx-arm64 --output game-builds/CollisionLab
python3 engine/tests/CollisionLab.Spatial/verify.py --player game-builds/CollisionLab/CollisionLab.app/Contents/MacOS/MoNoonPlayer
```

Windows는 `win-x64`와 배포 폴더의 `MoNoonPlayer.exe`, Linux는 `linux-x64`와 `MoNoonPlayer`를 사용한다. 검증기는 임시 프로필에서 두 씬을 차례로 실행하고 대상 ID 해시, 표본 수, 후보 합계를 검사한다. 저장한 원본 로그도 `--log <경로>`로 재검사할 수 있다.
