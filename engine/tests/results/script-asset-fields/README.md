# KeyRoom 스크립트 Inspector와 문 스프라이트

2026-11-16, macOS 27.0.1 arm64. MoNoon.app에서 편집한 씬을 다시 열고, 같은 프로젝트를 Distribution 프로필의 Release와 Native AOT 앱으로 내보냈다. 샘플 원본은 프레임 1·2·3, Last, 오프셋 (0, 0)으로 열리도록 두었다.

1. 샘플 사본에서 **Key → KeySequence → Frames**의 두 번째 참조를 제거했다. Project에서 **DoorOpen2.png**를 검색해 헤더에 드래그하니 순서가 1·3·2가 됐다.
2. 목록의 마지막 항목을 첫 행에 놓아 2·1·3으로 바꿨다. **Cmd+Z** 한 번 후 1·3·2로 돌아왔고, 다시 옮겨 2·1·3으로 저장했다. 각 단계에서 씬 YAML의 에셋 GUID 순서를 대조했다.
3. 드롭다운에서 **RestFrame → First**를 선택하고 **Offset → X 24, Y -12**를 입력했다. 에디터를 종료하고 같은 프로젝트를 다시 열었을 때 세 필드가 모두 유지됐다. 별도 사본에서는 스크립트를 PNG 목록에 드롭해도 목록과 오브젝트의 컴포넌트가 그대로였으며 880 × 650 창에서도 좌표와 제거 버튼이 정렬됐다. [재열기](inspector.png) · [작은 창](compact.png)
4. 세 실행에서 왼쪽 방향키로 열쇠를 얻고 열림 애니메이션이 끝날 때까지 기다렸다. Scene Play의 Door Inspector에 **World 504, 70**, **Sprite Assets/DoorOpen2.png**, **Collider disabled**가 표시됐다. 오른쪽으로 이동해 문을 통과하고 두 번째 방에서 F5로 저장했다.

| 실행 | 문 위치·이미지 측정 | 화면 |
| --- | --- | --- |
| Scene Play | (504, 70)의 2,256개 픽셀 중심에서 열린 문 실루엣 일치 | [Scene Play](scene-play.png) |
| Release | 같은 위치에서 2,256개 일치 | [Release](release.png) |
| Native AOT | 같은 위치에서 2,256개 일치 | [Native AOT](native-aot.png) |

렌더링 비교는 아래쪽 고정 벽의 왼쪽 위 모서리 (480, 176)를 기준점으로 사용했다. 문은 원래 (480, 82)에 있다. 오프셋을 적용한 위치의 24 × 94 영역에서 원본 PNG의 픽셀 중심을 캡처 좌표로 환산해 샘플링했다. 세 실행 모두 문에 속한 768개와 배경에 속한 1,488개가 원본 PNG의 알파 마스크와 일치했다.
