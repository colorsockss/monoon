# SeedLab 턴 이동과 리플레이 검증

2026-11-14, macOS 27.0.1 (26A434), Apple Silicon arm64. 에디터에서 SeedLab의 Scene Play 버튼을 눌렀다. Release와 Native AOT는 내보낸 각 앱을 독립 실행했다. 창마다 사용자 데이터 폴더를 분리했다.

| 실행 | 플레이 중 대기 턴 | 같은 턴 재생 | 자동 재생 완료 |
| --- | --- | --- | --- |
| Scene Play | [4턴 기록](scene-play-live-4.png) | [4턴 재생](scene-play-step-4.png) | [8턴 완료](scene-play-auto-finish.png) |
| Release | [4턴 기록](release-live-4.png) | [4턴 재생](release-step-4.png) | [8턴 완료](release-auto-finish.png) |
| Native AOT | [4턴 기록](native-aot-live-4.png) | [4턴 재생](native-aot-step-4.png) | [8턴 완료](native-aot-auto-finish.png) |

세 창에서 **42**를 직접 입력하고 **Apply seed**를 클릭한 뒤 같은 키를 보냈다. 둘째 턴의 오른쪽 키는 0.65초 동안 눌렀다. **K**로 저장한 뒤 **N**으로 시드를 43으로 바꿨다. **J**를 눌러 저장된 시드를 복원하고, 미로 타일 375칸을 확인한 다음 한 턴씩 재생했다. 다섯째 턴 직전에 보낸 일반 이동 입력도 기록을 바꾸지 않았다. 마지막으로 **T**로 입구부터 자동 재생하고 최종 위치와 일치 메시지를 확인했다.

각 턴이 끝날 때마다 실제 창을 캡처해 탐험가가 그려진 타일을 찾았다. 입력으로 계산한 예상 좌표, 실제 플레이 좌표, 재생 좌표를 대조했다. 세 환경에서 각각 저장한 리플레이 파일도 바이트 단위로 일치했다. 두 배포 앱의 재생에는 Scene Play에서 만든 파일을 사용했다.

| 턴 | 입력 | 플레이와 재생에서 관찰한 타일 (X, Y) |
| --- | --- | --- |
| 1 | ← (벽) | (1, 1) |
| 2 | → (길게 누름) | (2, 1) |
| 3 | → | (3, 1) |
| 4 | Space (대기) | (3, 1) |
| 5 | ↓ | (3, 2) |
| 6 | ↓ | (3, 3) |
| 7 | ↓ | (3, 4) |
| 8 | ↑ | (3, 3) |

전체 회귀 검사 315개가 통과했다. 자동 검사에서는 새 세션에서 리플레이 불러오기, 잘못된 체크포인트 거부, 이동 규칙 변경 시 첫 불일치 턴에서 정지도 확인했다. [검사 로그](checks.txt)

에디터 창을 880×660으로 줄이고 10자리 시드 4294967295를 적용했다. 턴 표시와 재생 완료 문구, 입력 필드, 버튼이 화면 안에 정렬된 모습을 확인했다. [작은 창 화면](scene-play-compact.png)
