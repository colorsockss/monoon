# 2D 엔진 설계안 — 여러 카메라에서 독립 게임 빌드까지

첫 목표는 KeyRoom에 플레이어용 카메라와 문을 비추는 카메라를 함께 두는 것이다. 열쇠를 주우면 잠시 문 쪽을 보여 주고 다시 플레이어에게 돌아온다. 에디터의 Play와 독립 SDL 게임 창에서 같은 결과가 나와야 한다. 이후 목표는 코드 수정 없이 조작 키를 바꾸고, 재사용 가능한 방을 만들어 다음 씬으로 넘어가는 게임을 배포하는 것이다.

## 1. 여러 Camera 2D와 게임 시점 전환

### 사용 흐름

1. **Scene → Create Camera** 또는 **Add Component → Camera 2D**로 여러 오브젝트에 카메라를 둔다. 한 오브젝트에는 Camera 2D 하나를 붙인다. 각 카메라의 월드 위치와 Zoom이 촬영 영역을 정하고, 화면 비율은 기존 프로젝트 해상도를 따른다.
2. Inspector의 **Camera 2D → 시작 카메라로 지정**으로 Play의 첫 시점을 정한다. 지정된 카메라에는 같은 자리에 **시작 카메라**라고 표시한다. Hierarchy에서 다른 카메라를 선택하면 해당 카메라를 편집한다. 시작 카메라 변경은 별도의 명시적 동작이다.
3. Scene에는 모든 카메라의 중심과 촬영 테두리를 표시한다. 시작 카메라에는 이름 옆에 표식을 붙이고 선택한 카메라의 테두리를 강조한다. **Frame Camera**는 선택한 카메라에, 일반 오브젝트를 선택했을 때는 시작 카메라에 편집 화면을 맞춘다. 겹친 카메라는 Hierarchy에서 이름으로 선택할 수 있다.
4. 첫 버전은 **전체 게임 화면을 카메라 한 대가 촬영**하고 플레이 중 시점을 즉시 바꾼다. 미니맵·화면 분할처럼 둘 이상의 영상을 동시에 출력하는 기능은 후속 렌더링 단계다. 그 단계에서는 출력 영역, 그리기 순서, 배경 지우기와 포인터 좌표 변환을 함께 설계한다.

### 무엇을 어디에 저장하는가

| 상태 | 소유자 | 규칙 |
| --- | --- | --- |
| 시작 카메라 `defaultCameraId` | 씬 파일 | Camera 2D가 붙은 오브젝트의 GUID. 카메라가 있으면 유효한 ID 하나, 없으면 `null`. 이름 변경과 부모 이동에도 지정이 유지된다. |
| 현재 출력 카메라 `activeCameraId` | Play 세션 | 시작할 때 기본값을 복사한다. 게임 스크립트가 전환할 수 있고 Stop하면 폐기한다. |
| 편집 시점 | 에디터 Scene 뷰 | 기존 팬·줌을 유지한다. Play에서 카메라를 바꿔도 편집 화면 위치와 씬의 저장 상태는 그대로다. |

| 편집 동작 | 결과 |
| --- | --- |
| 첫 카메라 추가 / 이후 카메라 추가 | 첫 카메라를 시작 카메라로 지정한다. 이후에 추가한 카메라는 시점 전환에 사용할 수 있다. |
| 카메라나 카메라가 든 부모를 `⌘D`로 복제 | 위치·Zoom·자식·컴포넌트를 복제한다. 시작 카메라 지정은 원본에 유지한다. 복제 범위 안에서 카메라를 가리키는 스크립트 참조는 새 카메라로 연결한다. |
| 시작 카메라 오브젝트 삭제 / Camera 2D 제거 | 씬의 저장 순서상 남은 첫 카메라를 시작 카메라로 지정하고 상태줄에 이름을 표시한다. 부모 삭제로 카메라 자식이 한 단계 올라가기만 했다면 기존 지정이 유지된다. |
| 마지막 카메라 제거 | 빈 상태로 편집·저장할 수 있다. Play와 Save & Run을 누르면 카메라 추가 위치를 안내한다. |
| Undo / Redo | 오브젝트와 시작 카메라 ID를 같은 편집 기록에 넣는다. 삭제 후 자동 재지정까지 `⌘Z` 한 번에 복구한다. 시작 카메라 지정만 바꿔도 저장할 변경으로 인식한다. |

### 런타임과 기존 씬 호환

- **씬 형식 v6.** v5를 읽으면 기존 카메라의 오브젝트 ID를 시작값으로 채운다. 카메라가 없던 v4·v5 씬은 그 상태를 유지한다. v1~v3는 기존 로더가 생성하던 카메라를 그대로 시작 카메라로 지정한다. 버전 변환은 순서대로 적용하고, v5에 예전 Rectangle·스크립트 변환을 다시 적용하지 않는다. 파일은 사용자가 저장할 때 v6로 쓴다.
- **참조 검증.** v6에서 시작 ID가 없거나 깨져 있고 카메라가 남아 있으면, 첫 카메라를 임시 시작값으로 사용하고 에디터에 복구된 이름을 알린다. 다음 저장 때 수정값을 기록한다. 중복 오브젝트 ID나 잘못된 부모 관계는 기존 씬 검증 오류로 처리한다.
- **전환 API 제안.** 프로젝트 스크립트의 `ScriptTick`과 `ScriptContact` 양쪽에 같은 `Cameras.TrySetActive(Guid cameraObjectId)`를 제공한다. 대상이 현재 씬의 활성 Camera 2D 오브젝트면 전환을 요청하고, 잘못된 ID면 `false`를 반환한다. 한 고정 틱의 이동·트리거 처리가 끝난 뒤 마지막으로 요청된 유효한 카메라를 다음 그리기부터 쓴다. 두 카메라 사이의 위치는 보간하지 않고 새 카메라의 움직임만 기존 방식으로 보간한다.
- **플레이 중 비활성화.** 카메라 또는 그 상위 오브젝트가 비활성화되면 남아 있는 활성 카메라 중 시작 카메라를 우선하고, 그다음은 씬 순서를 따른다. 모두 비활성이면 배경만 그리고 시뮬레이션은 계속한다. 이 선택은 씬 파일에 기록하지 않는다.
- **구현 경계.** `Engine.Core`가 카메라 선택과 월드 좌표 → 게임 화면 변환을 소유한다. 현재 `SceneGame`은 생성 시 카메라 본체와 Zoom을 고정하므로 그리기 직전에 현재 카메라를 조회하도록 바꾼다. `Engine.Editor`에서는 생성·부착·계층 복제의 단일 카메라 제한, Scene 프레임 표시·선택, Undo 저장 단위를 함께 수정한다. 첫 버전에서 각 호스트는 기존 출력 표면에 게임 화면 한 장을 그린다.

### 첫 구현을 끝냈다고 판단할 기준

| 순서 | KeyRoom에서 확인할 결과 |
| --- | --- |
| 1A · 배치와 저장 | 기존 KeyRoom을 열었을 때 첫 화면이 같다. `DoorCamera`를 추가해 다른 Zoom을 주고 시작 카메라로 지정한다. 저장 후 다시 열면 두 카메라와 지정값이 남고, 내용이 같은 씬에서 Play와 Save & Run의 첫 화면이 일치한다. |
| 1A · 복제와 Undo | 카메라가 든 부모를 복제해도 원본이 시작 카메라다. 원본 Camera 2D를 제거하면 대체 카메라가 표시되고, Undo 한 번에 원래 컴포넌트와 시작 지정이 함께 돌아온다. 마지막 카메라 제거와 복구도 확인한다. |
| 1B · 게임 중 전환 | Player를 따라가는 카메라와 문을 향한 카메라를 둔다. 열쇠 접촉 시 문 쪽을 1초 보여 준 뒤 돌아온다. Stop 후 다시 Play하면 원래 시작 카메라에서 시작한다. |

KeyRoom의 기존 `Pickup`은 접촉하면 자기 자신과 문을 비활성화한다. 전환 예제에서는 열쇠 트리거에 프로젝트 스크립트를 두고, 수집 시 자식인 열쇠 그림과 문만 비활성화한다. 트리거는 중복 수집을 무시하고 고정 틱으로 1초를 센 뒤 플레이어 카메라로 복귀한다. `DoorCamera`는 문 바깥에 두어 문이 열려도 촬영을 계속한다. 이 구성은 새 전역 이벤트 시스템을 먼저 만들 필요 없이 시험할 수 있다.

## 2. 카메라 다음의 구현 순서

| 순서 | 기능과 설계 | 완료 기준 |
| --- | --- | --- |
| 2 | **입력 액션과 스크립트 디버깅.** 프로젝트 설정에 `Move` 같은 2축 액션과 `Interact` 같은 버튼 액션을 저장한다. Avalonia와 SDL 입력을 같은 고정 틱 입력으로 변환하고 기존 `tick.Direction`은 `Move`를 읽게 한다. Console에서 스크립트 오류의 파일과 줄을 열 수 있게 한다. | PlayerMovement를 고치지 않고 방향키와 WASD로 같은 속도로 이동한다. 짧게 누른 상호작용은 한 번만 처리된다. 고의로 낸 컴파일 오류를 Console에서 외부 에디터로 연다. |
| 3 | **에셋 ID와 프리팹.** PNG·씬·프리팹에 경로와 독립적인 ID를 부여하고 기존 PNG 경로를 처음 열 때 해석한다. Hierarchy의 하위 트리를 Project에 끌어 프리팹을 만들고 Scene에 끌어 인스턴스를 배치한다. 프리팹 내부의 로컬 ID와 인스턴스의 씬 GUID를 구분한다. 첫 범위는 원본 수정 전파와 인스턴스 위치 재정의다. 프리팹 바깥의 씬 오브젝트를 가리키는 참조는 배치한 인스턴스에서 지정한다. | PNG를 옮겨도 문 그림이 유지된다. 문 프리팹을 두 번 놓고 원본 스프라이트를 바꾸면 둘 다 갱신되며 각 문의 위치는 유지된다. 인스턴스 내부 참조가 옆 문으로 연결되지 않는다. |
| 4 | **씬 전환과 게임 상태.** 프로젝트에 시작 씬을 지정하고 스크립트에서 씬 ID로 다음 방을 요청한다. 다음 씬의 에셋과 스크립트를 준비한 뒤 틱 경계에서 교체한다. 열쇠 보유 여부처럼 씬을 넘어가는 값은 게임 세션에 둔다. | 출구를 통과하면 두 번째 방의 시작 카메라로 전환되고 열쇠 보유 상태가 이어진다. 실패한 로드는 현재 방을 유지하고 어떤 에셋이 필요한지 표시한다. Stop은 편집하던 씬으로 돌아간다. |
| 5 | **2D 표현과 피드백.** 먼저 Sprite Renderer에 레이어와 레이어 내 순서를 추가한다. 값이 같으면 기존 씬 순서를 사용한다. 다음으로 프레임·재생 시간이 든 스프라이트 애니메이션 클립, 효과음 재생, 화면 고정 텍스트·이미지 HUD를 붙인다. HUD는 월드를 그린 뒤 논리 게임 해상도 기준으로 그린다. | 문이 열리는 애니메이션과 효과음이 한 번 재생되고, 열쇠 아이콘은 카메라가 움직이거나 전환되어도 같은 화면 모서리에 남는다. |
| 6 | **독립 게임 빌드.** Build 메뉴에서 시작 씬과 포함할 씬을 정한다. 참조 에셋, 컴파일한 프로젝트 스크립트, 런타임과 플랫폼별 SDL 라이브러리를 묶는다. 빌드 전에 누락된 참조를 씬·오브젝트 이름과 함께 표시한다. | 이 맥에서 에디터를 닫고 내보낸 게임만으로 두 방을 플레이한다. 같은 프로젝트를 Windows x64·Linux x64 대상으로 패키징하고 각 OS에서 실행·입력·화면 비율을 별도로 검증한다. |

엔진은 카메라 선택, 입력, 에셋 참조, 충돌 이벤트처럼 여러 게임이 공유할 기능을 제공한다. 열쇠 수집, 문 열기, 카메라를 어느 때 몇 초간 전환할지는 KeyRoom의 프로젝트 스크립트가 결정한다.
